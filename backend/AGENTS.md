# 后端开发约定

本文件补充根目录 `AGENTS.md`，不替代它。

## 业务开发前的对接入口

先读 [接口总文档](../docs/api/README.md) 的通用协议，再按 [接入与验收指引](../docs/api/integration-guide.md) 的阶段和所有权实施。字段定义查 [模型说明](../docs/api/models.md) 与 [OpenAPI 草案](../docs/api/openapi.v1.json)，联调使用 [虚构样例](../docs/api/examples.json)，现有页面边界查 [前端交付范围](../docs/frontend-delivery.md)。这些是实现目标与对接依据，当前实现状态仍须检查本分支代码和测试。

- 后端 A：优先对齐公共会话／CSRF、错误、幂等、任务、产物与证据，再实现岗位规则、批次、初筛和聚合查询；统一维护公共模型和迁移顺序。
- 后端 B：优先核对已发布规则包、D01—D06 交接引用与当前有效性，再实现电话业务任务／尝试、联系前提、停止／核对、D07—D10、具体版本审核与导出；共用 A 的鉴权和公共查询格式。
- 现有内部事件的维护方式见 [合同说明](../docs/contracts/README.md)。不要用 HTTP 的可空来源读模型或本地模拟对象直接替换事件；尚未拨号时的电话来源及服务商原始回调适配，按接入指引中的未冻结项对齐，不擅自填成已发生的真实结果。
- 按接入指引的 `API-01`—`API-26` 选择本模块有针对性的验收，尤其验证并发、权限、版本冲突、外部结果不明和恢复。每实现一项，同步对应接口文档和实际验证状态；草案未覆盖或与现有实现冲突时先记录并对齐差异，不新增无说明的兼容分支。

## 实现与检查约定

- 使用 Python 3.12、FastAPI、Pydantic、SQLAlchemy 与 PostgreSQL；在本目录通过 uv 管理依赖和锁文件。
- A 维护 `core/`、启动入口与统一迁移；A/B 分别维护 `modules/intake/` 和 `modules/outreach/`。公共变更先同步合同，禁止新增另一套鉴权、任务或产物格式。
- 所有业务路由统一由 `app.main:create_app` 挂到 `/api/v1`。未实现的业务不添加伪成功接口。
- 初始化健康检查不是业务就绪承诺。数据库连接失败只返回稳定错误码，不透传 SQL、连接串和密钥。
- 业务实体、产物与文件必须进行对象归属校验；在鉴权实现前不要暴露真实业务入口或测试候选人数据。
- 使用数据库事务保证产物与待交接事件一致；不要用进程内临时任务承担外呼可靠性。
- 外部超时先核对实际状态，自动重试不等于自动重拨。报告审核绑定不可变版本。
- 更改 `core/contracts.py` 后更新导出 Schema、合同文档、样例与对应消费方。
- 检查：`uv run ruff check .`、`uv run ruff format --check .`、`uv run pytest`、`uv run python scripts/export_contract_schema.py --check`。
- 检查需要数据库、外部接口或 Docker 时说明实际验证环境；仅单元测试通过不能宣称真实电话已可用。
