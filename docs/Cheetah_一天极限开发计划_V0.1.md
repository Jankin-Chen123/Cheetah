## 1. 一天交付目标与成立条件

### 1.1 当天交付定义

交付一个可在受控环境运行的网页 MVP：猎头登录，创建岗位并粘贴 HR 需求／JD，审核岗位画像与筛选标准，批量导入简历，查看初筛；达标自动创建电话任务，完成真实测试电话或明确标注的模拟沟通，再生成内部评估和推荐草案，经猎头批准导出。

“简历推进报告”在当天统一解释为 PRD 的 D10 候选人推荐报告；推进进度显示在候选人时间线上，不新增第二套报告体系，也不自动推进 ATS、发送 HR 邮件或决定录用。

目标是完成一条可验证闭环，而不是一天内实现 V0.5 所有生产能力。本文列出的范围裁剪属于当日里程碑，不修改或取消 PRD 的长期要求。

### 1.2 人力与工时假设

- 至少三名熟悉各自技术栈的开发者：F 一名、A 一名、B 一名；可使用开发辅助工具，但不把其视为额外确定人力。
- 一名产品／业务决策者在关键节点可及时确认模板、规则和演示样本，最好另有一人兼任验收与环境协调；若没有，三位开发者必须预留交叉验收时间。
- 时间使用相对起点 H+N，不假设具体开工时刻。目标 H+10 功能冻结、H+12 完成受控环境验收；H+12—H+16 为故障缓冲，H+24 为硬截止。
- 不把连续通宵作为确定产能。主计划按约 12 小时工作窗口编排，包含交接和短暂休息；缓冲只处理阻塞，不追加功能。
- 技术栈须采用团队熟悉的组合。如果仅两人，或两名后端均不熟悉实时语音平台，本计划不承诺同等范围和真实电话当天完成。

### 1.3 开工第一小时必须核实

| 条件 | 需要拿到的具体材料 | 未满足时的处理 |
| --- | --- | --- |
| 模型能力 | 可用模型接口、结构化输出能力、额度与测试结果 | 样例响应仅用于并行开发；当天没有真实调用则 AI 能力未完成 |
| 检索能力 | 可用搜索接口、固定字段与允许来源 | 标记为未研究／人工补充，不把模型生成文本冒充联网事实 |
| 电话能力 | 可拨出线路、对话平台、回调、状态查询、停止／挂断接口及测试额度 | 切换模拟电话路径，真实电话交付项保持未完成 |
| 联系与告知 | 已同意测试的号码、可联系前提、AI 与录音转写告知、停止规则 | 只做内部模拟，不向真实候选人外呼 |
| 业务标准 | 一份岗位材料、初筛标准、评估维度、推荐条件及报告示例 | 使用明确标注的测试规则，仅验证流程，不声称专业筛选质量达标 |
| 部署条件 | 已有主机或可用受控环境；真实电话需要服务商可达的 HTTPS 回调地址 | 先做本地／内网演示；外部回调无法到达则真实电话未验收 |

真实电话要在一天完成，优先使用已有“外呼＋实时语音对话＋转写＋回调＋停止”平台。只有原始拨号接口、需要从零组装流式语音识别和合成时，不按当天可完成的既定前提估算。

## 2. 当天范围：做什么、延后什么

| 能力 | 当天必须交付的最小版本 | 延后内容 |
| --- | --- | --- |

| 岗位需求 | 粘贴 HR 需求／JD，生成 D01/D02；简单表单修改、确认发布 | 原始录音上传转写、可视化规则设计器 |

| 简历导入 | 文本型 PDF、TXT、粘贴文本；小批量逐份处理 | 扫描 PDF OCR、复杂版式、压缩包、邮件导入；DOCX 仅在核心闭环完成后评估 |
| 研究与初筛 | 固定表单、有限搜索、来源和未知项；D03—D06；三分支 | 深度自动补搜、研究缓存、前置淘汰、模型自优化 |
| 电话任务 | 达标自动建任务，唯一任务、防重、联系前提、停止、状态与回调 | 复杂预约日历、自动多轮重拨、跨供应商线路切换 |
| 电话对话 | 有平台时使用平台实时能力；必问与少量专属追问、告知和结束 | 自研语音全栈、复杂情绪策略、长期对话记忆 |
| 评估推荐 | D08/D09、缺失标记；达标才有 D10；批准具体版本后导出 Markdown | 品牌化 Word/PDF、邮件自动外发、HR 门户 |
| 运行控制 | 数据库存储任务、有限重试、版本引用、基础成本上限、错误可见 | 复杂监控平台、完整灾备、多实例高可用、计费结算 |
| 更正处理 | 保存新版本、旧结果失效、阻止失效报告交付；显式重算内部步骤 | 复杂字段级自动依赖推导、已交付材料自动通知 |

首日仅对限定测试样本验证。初始工程配置建议每批不超过 10 份、简历处理并发为 2；这些是待验证的测试限额，不是产品容量承诺或招聘评分规则。

绝不为了赶工省略：登录与对象权限、联系方式／授权检查、电话业务防重、候选人停止、未知证据标识、未达标不生成推荐、未审核不对外交付。

## 3. 开发架构与人员责任

### 3.1 两个后端工作包，共用一个后端工程

当天采用一个后端工程、一个数据库，按模块并行开发。前后端通过固定 API 分离；A/B 之间通过明确数据合同和持久化任务交接，不要求先拆两个微服务。

部署可运行一个 API 进程和独立后台执行进程。电话平台承担实时会话；回调只更新状态并登记后台任务，不在回调请求里执行完整模型评估。

建议默认技术栈：前端 React、TypeScript、Vite、Ant Design；后端 Python、FastAPI、Pydantic、SQLAlchemy；PostgreSQL；文本 PDF 提取采用成熟库。若团队已有更熟悉且可复用的栈，应在 H+0.5 前整体替换方案，不在冲刺中途换栈。

首日不引入九个独立服务、向量数据库、复杂 Agent 协商、完整工作流引擎或多个消息中间件。用持久化任务表完成最小调度；任务领取、重启恢复和外部结果不明处理仍必须可靠。

### 3.2 责任表

| 工作项 | F：前端 | A：后端前半段 | B：后端后半段 | 协调／验收 |
| --- | --- | --- | --- | --- |
| 页面与交互 | 主责，全部页面与统一请求层 | 提供前半段数据和错误枚举 | 提供电话与报告数据 | 确认流程与信息表达 |
| 岗位与规则 | 表单、草案、发布操作 | 主责 D01/D02、初筛与推荐规则包 | 评审 D02、推荐条件和电话输入是否足够 | 确认业务标准 |
| 简历与初筛 | 上传、进度、D03—D06 展示 | 主责 A03/A04/A05、批次和初筛 | 使用固定样例独立联调 | 提供三类预期样本 |
| 电话与报告 | 电话状态、D07—D10、审核导出 | 提供有效输入和取消／失效事件 | 主责 A06—A09、适配器、停止、防重与回调 | 确认测试号码和告知 |
| 公共基础 | 错误、登录过期、状态轮询 | 主责 API 启动、鉴权、数据库基线、任务与产物公共组件 | 评审并使用公共组件，不自行另建一套 | 环境和关键决策 |
| 集成与发布 | 前端构建、同源 API 路由 | 主责部署清单和后端集成；每次集成窗口合并 | 主责电话入口可达性和服务商核对 | 跑验收、记录未完成项 |

A 公共基础任务必须限时：先提供公共组件接口和可运行骨架，不能先做完整平台再开发前半段业务。B 在固定合同和样例下开工，不等待 A 的真实 AI 输出。

## 4. H+1 前必须冻结的协作合同

### 4.1 公共约定

| 项目 | 约定 |
| --- | --- |
| API | 统一 `/api/v1`；前端不分别访问两套后端域名 |
| 时间与 ID | 服务端生成不可猜测 ID；时间为带时区的 ISO 8601，前端按北京时间展示 |
| 同步／异步 | 创建对象可同步；模型、研究、批次和报告生成返回 `202 + task_id`，实际状态持久化 |
| 查询 | 前端默认约 3 秒轮询活动任务，结束或离开页面停止轮询；无数据时显示等待，不伪造百分比 |
| 分页 | 候选人、批次与电话列表统一 `items/total/page/page_size` |
| 错误 | `{code,message,request_id,details}`；区分未登录、无权限、规则未发布、条件不满足、外部待核对、预算不足 |
| 产物 | 公共 `artifact_id/type/version/status/input_refs/rule_pack_version/evidence_refs/source_mode` |
| 来源标识 | 模型、检索、电话分别记录真实／模拟／人工来源；上游模拟不能因下游真实模型调用而消失 |
| 测试配置 | 测试规则、测试号码、模拟入口显式隔离；真实号码外呼受允许名单和联系前提约束 |

不能仅给前端几个成功 JSON；至少提供成功、处理中、失败、信息不足、拒绝和待审核六类样例。

### 4.2 当天核心 API 清单

下表是开工合同草案，H+1 时由三方转成 OpenAPI 并冻结字段。接口名称可统一调整，不能各自开发不同语义。

| 接口 | 负责人 | 关键输入／返回 |
| --- | --- | --- |
| `POST /auth/login`、`POST /auth/logout`、`GET /auth/me` | A | 预置账号登录；安全会话；浏览器可获取用户和机构范围 |
| `POST /jobs`、`GET /jobs`、`GET /jobs/{id}` | A | 创建岗位、列表、材料与规则状态 |
| `POST /jobs/{id}/analyze` | A | 异步生成 D01/D02；返回任务 ID |
| `GET/PATCH /jobs/{id}/rules/draft` | A | 修改草案与规则；带期望版本，避免覆盖别人的修改 |
| `POST /jobs/{id}/rules/publish` | A | 发布指定版本，返回不可变规则包版本 |
| `POST /jobs/{id}/resume-batches` | A | 文件／文本批次；返回批次和单份记录 |
| `GET /batches/{id}` | A | 总数、各状态数量、单份任务和错误 |
| `GET /jobs/{id}/applications` | A | 候选人岗位关联、初筛状态、后半段摘要 |
| `GET /applications/{id}` | A，B 提供固定摘要字段 | 当前阶段、产物引用、电话与报告摘要 |
| `GET /applications/{id}/artifacts` | A 的公共查询，A/B 按产物类型写入 | 按 D 类型查询；同时校验对象权限与版本 |
| `GET /evidence/{id}`、`GET /files/{id}` | A 公共实现，A/B 通过合同写入证据 | 查看来源、原文位置或授权下载原文件；不得绕过归属、删除和访问限制 |
| `GET /tasks/{id}`、`POST /tasks/{id}/retry` | A 公共实现，B 注册任务类型 | 只允许已定义的内部计算重试；不能当成通用重拨入口 |
| `POST /applications/{id}/contact-authorization` | B | 联系前提记录、来源和有效状态；不是前端传 `true` 即视为已获授权 |
| `GET /calls`、`GET /calls/{id}` | B | 电话业务任务、每次尝试、会话与真实通信状态 |
| `POST /calls/{id}/cancel` | B | 排队时取消；进行中请求停止，收到确认前显示“停止请求中” |
| `POST /integrations/voice/callback` | B | 验证服务商签名或约定凭据；不依赖猎头浏览器会话 |
| `POST /reports/{id}/review` | B | `expected_version + approve/reject + reason`；绑定报告具体版本 |
| `POST /reports/{id}/regenerate` | B | 仅重生成内部结果；不重拨、不自动批准或外发 |
| `GET /reports/{id}/export` | B | 仅导出有效且已批准 D10，返回 Markdown 附件并登记导出 |
| `GET /health` | A，B 提供依赖检查 | 基础运行、数据库及关键接口配置状态，不返回密钥 |

首日 UI 不提供“逐人开始电话”按钮。达标自动建任务，用户只补充前提、查看等待原因、取消或请求停止。

### 4.3 A/B 交接合同

**交接时机：** D06 已持久化、初筛规则核验为达标后，A 在同一数据库事务登记 `screening.passed` 待交接事件；B 领取后，在同一事务创建或找到已有电话业务任务并确认消费。进程退出后仍可继续，不能只通过内存函数或“发送过一次 HTTP”交接。

**交接内容：** 岗位候选人关联、有效规则包、D01—D06 引用、证据引用、联系前提记录引用、材料与规则版本、测试／真实来源标识，以及业务防重标识。B 根据合同读取不可变快照，不反复要求 A 拼接完整自然语言材料。

**前提检查：** B 不仅信任事件中的“已达标”，还检查任务未取消、证据版本有效、规则已发布、现有电话业务状态与当前联系前提。信息不足和暂不推荐不发布电话创建事件。

**防重层次：** 事件 ID 去重；电话任务按岗位候选人关联检查有效任务；同一候选人正在外呼时阻止其他岗位并发触达；拨打尝试记录独立请求标识。换规则版本、重做提纲或重放事件都不自动获得第二次拨打机会。

事件示例见 `docs/contracts/day1_screening_passed.example.json`。示例仅定义数据形状，不证明已有接口或业务执行结果。

### 4.4 公共数据与写入归属

| 对象 | 主责 | 另一方的使用方式 |
| --- | --- | --- |
| 用户、机构、岗位、规则包、简历文件、岗位候选人关联、批次 | A | B 通过公共读取服务访问，不自行改写已发布规则 |
| 电话业务任务、拨打尝试、联系前提记录、回调记录 | B | A 读取统一摘要，不直接把技术失败写成初筛失败 |
| D01—D06 | A | B 按引用读取不可变输入 |
| D07—D10、报告审核与导出记录 | B | A/F 通过公共查询展示 |
| 任务、产物、证据、交接事件、用量 | A 维护结构，A/B 分类型写入 | 表结构变更统一迁移；不可各自建立不兼容字段 |

公共表可以采用少量 JSON 字段承载各 D 类型内容，前提是通过 Pydantic 校验、版本化和证据引用；不为十种产物各建一整套 CRUD 后台。

## 5. 前端 F：页面和任务拆分

采用一个网页工作台，复用布局、状态标签、产物查看器、证据抽屉和任务提示。当天不建设独立 HR 门户、候选人门户或复杂流程画布。

| 编号 | 页面／功能 | 关键交互与验收 | 时间块 |
| --- | --- | --- | --- |
| FE-01 | 工程、布局、登录和请求层 | 登录过期可处理；所有页面走统一 API；以组件库默认样式为主 | H+0—H+1.5 |
| FE-02 | 岗位列表／新建 | 粘贴需求，提交后跳转岗位详情并展示生成状态 | H+1.5—H+2.5 |
| FE-03 | 岗位详情与规则确认 | D01/D02 可读、草案可编辑；缺失与未知可见；发布版本明确 | H+2.5—H+3.5 |

### 8.2 集成纪律

H+1、H+4、H+6、H+8、H+10 设置固定交接检查，检查有结果则直接继续。关键阻塞超过 15 分钟须通知接口负责人；超过 30 分钟由协调者选择缩范围或明确未完成，不让一人等另一人半天。

合同调整必须同时更新接口、样例和前端适配；H+6 后不随意改公共字段。每个工作包提交可运行的小增量，H+8 前不能出现“各自写完，但从未启动在一起”的情况。

## 11. 环境、部署与回退

### 11.1 环境分离

开发阶段前端独立服务并代理 API；受控部署时静态前端与 `/api/v1` 统一入口，减少跨域和登录配置耗时。前后端仍保持工程和接口分离。

后端密钥仅在服务器配置，不进入前端包、仓库或日志。可提交无真实凭据的配置示例，列出模型、搜索、语音、数据库、会话、预算、测试号码和模式开关。

数据库、上传文件与产物存储持久化。回调入口验证来源，模拟回调不能作为未鉴权的公开任意状态修改入口；本地测试可使用专用签名与测试环境限制。

部署访问默认受控，不因准备演示就开放生产候选人数据。实际发布或开放公网应在环境和授权明确后执行，本计划本身不代表已部署。

### 11.2 回退顺序

1. 先关闭新外呼与新交付入口，阻止继续产生外部动作。
2. 核对进行中的电话与外部结果不明任务；必要时请求停止，不把数据库回滚当成真实电话已停止。
3. 保留数据库、外部请求标识、拨打尝试和审计记录，恢复上一个可运行代码版本。
4. 重新启动后先核对未完成外部动作，再恢复队列；不能清空任务表后重新跑全部候选人。

## 13. 一天之后的优先补齐项

在当天验收证据基础上排期，不提前承诺固定天数：补齐未完成的真实电话／搜索依赖；完成正式业务模板与质量评审；完善生命周期、备份与审计；增加文件类型与容量验证；补齐预约、合法重拨和更正依赖传播；最后再考虑研究缓存、前置筛选、多机构运营和 ATS 集成。

本计划的执行顺序是：先冻结合同并验证最大外部依赖，再三线并行形成可运行小闭环，H+8 进入端到端联调，H+10 前完成主链验证，最后把时间用于关键控制、部署与验收。
