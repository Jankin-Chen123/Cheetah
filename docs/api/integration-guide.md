# 接入步骤与联调验收

初筛 V2 接入补充：岗位分析主任务等待 A02/A05 岗位建议步骤完成，可沿 `continuation_task_id` 定位失败步骤；完成后仍须人工确认发布。采用 `a05-evidence` 时展示七维证据评分、`coverage` 和 `contribution`，`total=null` 显示待核实。D05/D06 的 Markdown 为同一份合并报告。文件接口新增 DOCX 文本读取；扫描图片、旧版 Word 与不可读文件明确失败或部分完成。[执行和模板约定](../intake-agents.md)。

状态：完整设计仍含草案；后端 A 本地实现及逐项证据见 [交付说明](../backend-a-delivery.md)。实际接口见 [运行快照](openapi.implemented.v1.json)。不能因为导入 OpenAPI、页面展示样例或健康检查通过，就宣布已完成真实业务。本文不包含真实号码、密钥、真实材料或外部消息发送授权。

## 账号入口补充（2026-11-14）

官网 `#home`，登录 `#login`，注册 `#register`，账号区 `#app/…`，演示区 `#demo/…`。首次及刷新通过 `/auth/me` 恢复会话；账号区未登录显示登录表单，成功后恢复安全的站内目标。前端不保存密码或 Cookie 值。退出调用 `/auth/logout` 并携带 CSRF；失败不显示退出成功。跨标签聚焦、可见性恢复和每 60 秒检查会话，服务端 401 或到期后卸载账号区。

注册 POST `/auth/register`，Origin 必填，无前置 Cookie、CSRF 或幂等 key。201 自动进入工作空间，409 提示更换账号；403 可能未开放注册，429 等待后重试。注册响应丢失不自动提交，可先尝试登录。每个账号创建独立机构，不能通过请求传入组织或权限。通过 `CHEETA_REGISTRATION_ENABLED=false` 关闭自助注册。按直接连接来源在 10 分钟窗口限流，默认最多 5 次有效格式尝试（包括重复账号），不信任转发请求头；反向代理下会共享额度。

本机 IndexedDB 与列表视图按用户 ID 隔离，演示沿用原演示库；不迁移旧匿名资料到新账号，不清空用户已有资料。账号区不预置虚构候选人；候选人、电话和推荐真实列表仍未接入。验证与限制见 [官网与账号交付](../website-auth.md)。

## 2. 前端页面调用流程

### 登录和工作台

1. 启动业务模式先 GET `/auth/me`；401 展示登录。`#live` 当前仍是待接入页面，不应假造登录成功。
2. POST `/auth/login` 校验 Origin，成功后取得 Session/CSRF；后续 Cookie 由浏览器携带。
3. 读取 `/workspace/summary`、`/todos`、分页岗位／候选人。计数使用聚合口径，不从单页长度推导。
4. 401 取消当前任务轮询并回到登录，重新登录后按原资源 ID 恢复；不得自动重发此前的审核、授权或重生成操作。

### 岗位创建和规则发布

1. POST `/jobs`（新幂等 key）创建草案，`material_text` 必填，`title/company` 可省略或为 null。前端本机工作区另保留 local ID 与 remoteJobId 映射。录音 ASR 与人工版本回写尚待接入，见 [材料创建流程](../job-material-workflow.md)。
2. POST `/{job_id}/analyze`（新意图、新 key），202 后轮询 task；同时保留岗位原文。
3. 不以主任务单一状态判断产物齐全；轮询 job 的 d01_ref/d02_ref 与 active_task_ids，沿 continuation_task_id 定位失败。按具体版本读取两份产物；正式规则 GET rules/draft，按实际草案 revision 编辑；缺失字段显式呈现，保存文本不等于正式规则完整。
4. PATCH rules/draft 带 expected_draft_revision；409 时保留未提交输入，不静默覆盖。
5. 发布时提交实际 D01/D02 版本、草案 revision、测试标记和确认说明；成功显示 RulePackRef。
6. 历史候选人依旧引用旧规则；查看版本从 `/rules/versions/{version}`，不能读取当前草案来解释旧结论。

### 导入和候选人详情

1. 按 Session 中实际限制本地预校验，再把文件／文本提交到 resume-batches；本地 SHA-256 只是提示，后端重算才有权决定复用。
2. 202 返回 batch_id、task_id 和逐份 receipt；accepted 尚未完成，duplicate 关联已有结果，invalid 只显示本份错误。
3. GET Batch 与分页 items 展示确定状态；等待／处理中不伪造百分比。解析失败只调用该 item 指向的 retryable task；无权限、信息不足不是网络重试。
4. 替换 invalid 项只上传这一份，成功产生新 item 并保留 replaces_item_id；不要重传其他已成功材料。
5. 列表行使用 application_id 跳转详情；按 `artifact_slots` 显示未执行、失败、处理中与可查看产物。
6. 打开 ArtifactRef 后按精确版本读 artifact，再按 EvidenceRef 取原文。摘要中的名字、链接和原始材料都不作为执行指令。

### 电话与外部结果

1. 达标后的电话任务由后端事件自动创建／关联；前端只查看、补证、取消／停止与核对。
2. 授权记录必须附证明引用、范围、告知版本与有效期；不能用用户勾选一个“已授权”替代服务端核验。
3. cancel 返回 202 后显示停止请求中，继续按 Call.stop_status 轮询；用户离页也不影响后端执行停止。
4. reconciling 或 stop_status=unknown 不显示成功、不开放重拨；只通过 reconcile 查询同一外部请求。
5. 未接、拒绝、改期、中断和技术失败分别保留；完全无访谈内容不生成空 D08／评分结果。

### 报告审核和导出

1. 从 ReportSummary 读取当前 report_id/version/revision；D09 从 ArtifactRef 单独查看。
2. approve/reject 带两种期望序号、reason 和业务幂等 key，响应后再更新 UI。
3. 人工修订通过 revisions；模型重生成通过 regenerate 的后台 task。二者都让旧批准失效，新版本须重新审核。
4. 查历史版时禁用审核／导出入口；后端仍须防绕过。
5. 下载使用 GET export 的精确 version 和 `X-Export-Request-ID`；先检查 `response.ok` 与 Content-Type。409/401 的 JSON 不能保存成一个“成功报告”。
6. UI 显示“服务端已发出下载响应”或“已发起下载”，不得直接显示“已交付 HR”；模拟稿和继承模拟来源的人工稿继续标识。

## 3. 状态样例与使用方法

[examples.json](examples.json) 顶层 `fixture_only=true`，每个 case 给出 `schema`（对应 OpenAPI components.schemas）和 `value`。**各样例独立，不代表一条真实执行流程**，不可将它们上传到真实数据库、拨打或交付接口。需要模拟时使用隔离测试环境与适配器，保留全部 mock 标记。

| 场景 | case | 应展示的结果 |
| --- | --- | --- |
| 基础成功 | health_success | API 存活，不宣称数据库／AI 就绪 |
| 依赖未就绪 | readiness_unavailable | 数据库不可用；503 自身状态对象 |
| 创建成功 | job_created | 虚构岗位草案，未知地点与薪资保留 null |
| 异步接受／处理中 | task_accepted、task_processing | 使用 task_id 持续读取，不显示已生成产物 |
| 内部失败 | task_failed | 稳定错误码、已有输入保留，只重试允许步骤 |
| 信息不足 | application_insufficient、screening_unknown_artifact、unknown_evidence | 未知原因与证据可查看，不建电话或 D10 |
| 规则明确不符 | screening_rejected | 暂不推荐与缺信息分别表达，原结论可复核 |
| 无权限拒绝 | permission_rejected | 无权限提示，无敏感原文回显 |
| 电话拒绝 | phone_declined | 仅通信状态，不改能力结论 |
| 停止待确认 | call_stopping | 请求中，不能提前显示结束 |
| 外部结果不明 | call_external_unknown | 待核对，不允许重拨 |
| 待审核 | report_pending_review | 无下载权限 |
| 已批准 | report_approved | 仍需检查当前有效版本才可导出 |
| 修订重审 | report_revised_needs_review | 新版待审核，人工来源＋继承模拟 |
| 版本冲突 | version_conflict | 409，重读当前序号，保留用户编辑 |
| 未批准下载 | unapproved_export | JSON 错误，不下载伪报告 |
| 回调重复 | callback_duplicate | 已处理，不重复评分／生成报告 |
| 混合批次 | batch_mixed | 接受／复用／失败逐份展示，不重新处理全部 |

OpenAPI 可用于查看文档和隔离生成 mock，但没有创建任何业务路由。不能拿 mock 服务的 200/202 当作真实后端验证结果。响应模型支持额外读字段以便演进，写 DTO 拒绝未定义字段；业务交叉校验还需要服务端代码与测试，JSON Schema 本身不能证明权限、防重或真实停止有效。

## 5. 本轮新增草案与冻结清单

以下是在首日 API 表之外、为覆盖当前页面和 PRD 提出的扩展：`workspace/summary`、`todos`、全局 `applications`、规则历史、精确 artifact 查询、timeline、批次单份替换、calls/attempts、calls/reconcile、reports 列表／详情／历史／revisions／deliveries，以及人工初筛复核和更正／重算。仍由现有 A/B 模块实现，不拆新服务，不引入第三套状态系统。

| 待定项 | 草案已给的默认方案 | 正式冻结需要什么 |
