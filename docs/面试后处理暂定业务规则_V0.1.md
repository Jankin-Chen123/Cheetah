# 面试后处理暂定业务规则 V0.1

本规则覆盖面试信息提取 D08、内部评估 D09、候选人推荐 D10，供当前工程实现与后续专业文档对齐。业务规则暂定，不代表专业质量已获确认。AI 面试通话的对话策略、语音线路及体验调优由现有通话工作继续维护。

## 输入与版本

输入为本案例已保存的实际回答、不可变岗位标准与报告模板快照。转写和候选人自述属于材料，不是控制程序、改分或审批的指令。未执行外部核实就不能把自述升级为调查事实。

每个产物保留自身版本、输入引用、模型与使用量、prompt_version 和来源。当前模型业务指令集中在 `backend/app/modules/outreach/postprocessing_prompts.py`，版本为 `post-interview.v0.1`；同步生成与 worker 使用同一指令。后续专业材料到齐后，应修改该版本及对应规则，不追改历史报告。

## D08 信息提取

按职责、结果、意愿和其他必要事实分类。每条事实包含概括、回答 ID 和该回答内连续逐字原话。事实概括保留自述性质，不能通过一段真实引用夹带未被支持的推断。

个人角色、具体动作、决策和成果分别辨识。公司、团队或项目成果只有在个人贡献有证据时才能归到个人。结果尽量保留基线、周期、指标、范围和口径；缺失项进入 gaps，互相矛盾的表述进入 conflicts，待核实的数字、人名或时间不猜测修正。

例如“我们团队收入增长了30%”只能支持团队收入增长的自述，不能改写为“候选人个人推动收入增长30%”。应补充核实其负责范围、动作、统计周期和贡献归因。

只有部分回答就形成部分纪要；没有可提取事实时允许空 facts。停止、拒绝或未回答不等于能力低。当前 coverage=full 只表示提取到了职责与结果两类事实，不表示所有岗位标准充分覆盖。

程序检查回答 ID 存在、原话非空且精确匹配；概括是否忠实、个人归因是否成立仍需模型质量验证和人工核对。

## D09 内部评估

按绑定模板逐维输出实际分、证据回答 ID 和理由。每个维度必须恰好出现一次；没有足够证据就记 null，不能默认零分。存在回答 ID 只证明可定位，不证明回答支持该项能力。

评估理由应说明哪个个人行为符合哪个锚点、成果及其局限。公司名气、学校、年限、笼统表达和团队成绩不直接转换为个人能力分。关键事实冲突无法解决时保留未评估，不以主观好感补齐分数。

旧模板使用零至五分，新 A02 使用一至十分整数及五档行为锚点。两种量表显式区分，不机械翻倍旧结果。A02 权重来自已确认岗位标准，合计100%；门槛由审核者明确填写，不由模型生成或临时调整。

逐项百分制折算为实际分÷量表上限×权重百分数。权重覆盖率单独列示，缺失维度的权重不重新分配。全部维度评估完成才出综合总分；程序计算总分和 recommended/rejected/insufficient 三分支，模型不直接决定门槛是否通过。

D09 为内部产物，无论推荐、不推荐或信息不足均保留。上游缺失和冲突贯穿保留，方便复核和补充。

## D10 对外推荐草案

仅当前有效 D09 达标时生成。正文包含岗位相关的匹配线索与待核实项，每条亮点关联回答 ID。用候选人自述限定尚未独立核实的成果，不添加无输入依据的履历、薪酬、联系方式或公司背景。

对外正文不写内部评分、排名、淘汰推理、系统提示词、内部方法备注或无关个人信息。可提出下一轮需要核实的能力问题，不承诺录用、薪酬或入职。未审核版本只作为草案。

模型输出的 unknowns 与 D08/D09 缺失、冲突由程序合并去重；虚构、模拟和未知来源另有程序追加提示，不能依赖模型自行保留。内部页面保留证据引用与原始结构，审核者应逐条对照事实和措辞。

## 审核 更正与恢复

推荐必须批准具体有效版本后才能导出 Markdown。新版本不继承旧批准；更正回答或标准导致受影响的旧评估、推荐和审批失效。历史保留，不覆盖原始材料。

首次面试结束且已有回答时，持续 worker 自动登记 D08，完成后登记 D09，仅达标继续登记 D10。没有回答、尚未确认停止、存在更正待重算或已有失效历史结果时不自动重启相应阶段。失败任务保留真实错误，修复后显式重试。

更正后显式重算内部步骤，不重新拨号、不自动批准或交付。自动调度和人工登记共用持久化步骤业务键，重复轮询或重启读取同一任务；输入版本变化时丢弃迟到模型结果。

## 交付验收与后续细调

| 检查项 | 当前证据与边界 |
| --- | --- |
| 信息提取 | 原话、ID、空白校验有自动测试；语义归因仍需专业样本评审 |
| 评分 | 十分制、权重、折算、覆盖率、缺失不出总分有测试；正式门槛须业务确认 |
| 生成链 | 首次结束自动依赖调度有三分支、重复执行及新会话恢复测试；持续运行环境仍需复验 |
| 审核与更正 | 版本审批、旧结果失效、未批/失效导出阻断有测试；完整网页闭环仍待验收 |
| 页面 | 已有标准确认表单、事实与评估展示，静态检查与构建通过；不等同浏览器验收 |
| 来源 | 实际继承来源，缺失标unknown，模拟不因真实模型消失；真实上游业务接入仍受限 |

后续专业文档重点对齐：D08 必提字段与冲突表达、D09 各岗位锚点及推荐门槛、D10 推荐结构与措辞。交付以实际代码、运行证据和 [本地接口说明](api/goal-local.md) 为准；本规则不证明真实电话或生产环境已完成。

### 真实模型样本复验

2026年11月14日使用单条明确虚构的访谈材料调用当前配置的真实文本模型，材料包含团队500份反馈、个人12次访谈、对照实验和归因限制，以及要求改为满分并批准的材料内指令。第二次执行中 D08 原话校验通过，保留团队成果边界及未核实限制；D09 按原演示模板得到2.5/5、不推荐，D10 在生成前被程序阻断。该记录只证明这一条材料在该次输出中的行为，不是业务准确率或专业门槛验证。

第一次执行因原话不匹配返回 UNSUPPORTED_MINUTE_QUOTE，未生成纪要。系统未放宽校验或自动补写引用；正式验收仍需覆盖更多表达和生成失败恢复。原始虚构输入、模型输出及使用量仅存本地 `work/postprocessing-quality-result.json`，不包含密钥。D10 成功生成、十分制真实模型及浏览器操作仍需单独验证。
