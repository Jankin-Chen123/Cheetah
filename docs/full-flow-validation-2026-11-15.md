# 岗位至文字面试与推荐核验（2026-11-15）

## 范围与环境

目标网站为 cheetah.asia。线上使用独立测试账号复现岗位创建失败：D01 已生成，约 42 秒后 D02 步骤返回 INVALID_MODEL_OUTPUT。该次 worker 实际运行，不能归因为执行器未启动。线上未配置语音；按用户要求，仅核验文字对话与报告。

修复在本地隔离数据库与测试账号验证，未部署至生产。内测材料明确声明为虚构候选人；真实模型执行不改变材料的虚构属性。测试规则保持 is_test_rule=true、交接 fixture_only=true、phone_execution_mode=mock，不拨号、不发邮件、不向客户发送报告。账号、原文、模型响应与受限邀请均留在忽略的 work/ 中，不提交。

## 本轮修复

- 岗位任务 queued 超过 90 秒显示“等待后台处理”，reconciling 显示“结果待核对”，不再无限灰显。保留原任务，支持重新检查。运行超过 10 分钟结束前端等待，不取消后台工作。
- POST /tasks/{task_id}/regenerate：仅已确认的坏输出可显式重新调用一次；保留旧任务与调用结算，校验归属、revision、材料版本、预算和幂等。未知、运行中、已发布或已被接替的任务不得重新生成。人才默认调用预算为 2。
- 原文引用兼容空白及成对 Markdown 强调符号，始终定位原文连续片段；不能拼接不相邻原文。提取提示进一步要求 stated.value 为 quote 的连续摘录，避免合法引用配上改写值而降为未知。
- 岗位页面新增独立初筛／面试标准确认发布、推荐门槛与取证维度。岗位名、企业名可在创建时补充；匿名企业不自动补造。
- 人才库失败提取可在同一份材料上重新生成；中文职能搜索按显示名称匹配；岗位明确设置接收方向后分流。
- 初筛详情新增人工复核入口，绑定当前 D06、理由和有效证据，保存新版本，保留缺口与旧结果。
- 面试 worker 消费经过数据库再次校验的 screening.passed 1.1 outbox，同事务防重创建案例，绑定已发布 A02 的权重、锚点与门槛。原 D06 的失效事件不能误伤绑定新版 D06 的新案例；实际受影响的案例使旧 D07—D10 失效，进行中仅请求停止。
- 显式 CHEETA_TEXT_PROVIDER=configured 可复用既有 HTTPS 结构化模型完成文字提纲、追问和报告。不依赖语音或邮件凭据，不静默切换模型服务商。
- 候选人 /candidate/text#call=…&token=… 提供逐项许可、求职意愿、岗位资料确认、文字问答及停止；邀请只在本次面试有效，不自动发送。
- D07 题目时间由程序分配固定 26 分钟，保留模型原始建议时间供追溯；题目、维度、证据和得分不因此改变。来源、全维度覆盖、条件追问及单目标独立审查保持校验。
- 文字对话的“仅确认、没有下一问”转入未问的准备问题；候选人正在提问时保留直接答复。换题优先未问维度；问句只增加口语前缀时仍关联原始准备问题，不伪造回答或充分性。
- 前端展示面试失败步骤的有限重试；结果不明或输入失效不能重试。D07 恢复时限覆盖 configured 服务四次有界模型调用。
- 候选人页面刷新后从受限会话恢复本人已提交的问答；不暴露内部评估、模型上下文或其他来源的开发样例。
- 完整简历表单中的项目名称、角色、职责、结果映射至职业资料；保留人工逐字段确认。被驳回的具体报告版本可以显式生成新版，旧版仍失效且不可交付。

## 协议与使用

实际字段以 docs/api/openapi.implemented.v1.json 为准，frontend/src/api/generated.ts 从该文件生成。完整设计稿另同步新增任务端点与 calls.application_id 查询；内部事件模型未变，继续使用 core/contracts.py 导出的 1.1 合同。

真实模型可在显式 allow_mock=true 的隔离环境处理测试规则，但保持其测试来源；mock 提取仍不能进入真实规则。生产默认关闭 allow_mock。未知项保留，真实业务发布前仍需招聘方确认完整标准。

线上 SSH 连接本轮未成功，未修改生产代码、配置和数据库。因此线上卡住问题尚未验证修复；必须在获准上线后再做线上回归。

用户后续明确选择“先保留本地修复，暂不上线”。本轮遵循该选择，不再尝试服务器部署。
