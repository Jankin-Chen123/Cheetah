# 前端交互演示与后续接入

当前 personal/dev 另有 `/goal` 持久化验收入口，使用本地登录、PostgreSQL 电话任务、方法预览、模型队列、回答更正及具体版本审核下载。下文记录原内存演示工作区，不能用于判断 `/goal` 的实现或浏览器验收状态。最新运行方式与证据见 [Goal 验收说明](Goal_验收说明.md)，实际接口差异见 [本地 API 增量](api/goal-local.md)。

本轮交付 React / TypeScript / Ant Design 前端页面与本地状态交互，不代表真实业务闭环已完成。后端仍仅提供健康检查；不修改后端、公共交接模型或生成的 Schema。

## 启动与状态

在 `frontend/` 使用 Node.js 24，运行 `npm ci`、`npm run dev`，访问 `http://localhost:5173/`。生产构建运行 `npm run build`。本轮未部署、未提交或推送。

默认进入明确标记的演示工作区。全部姓名、企业、简历、电话与报告为虚构样例。岗位、规则、审核、材料摘要及下载请求仅保存在页面内存，不写入 localStorage / sessionStorage / IndexedDB；刷新清空。材料文本不会当作 HTML 或执行指令。

目前只有 `src/api/client.ts` 请求统一 `/api/v1/health`，保留超时、取消与响应校验。基础服务在线不代表数据库、登录、AI 或电话已就绪；登录入口明确显示待接入，不收集或存储密码，也不伪造成功会话。

## 接口接入边界

`src/domain/workspace.ts` 是本地演示模型，不是已冻结的公共 API 合同。后端实现前需要按开发计划冻结字段；不能将演示状态直接上传为真实业务结果。

详细的后续对接设计已补充到 [前后端接口文档](api/README.md)，包含 [OpenAPI 草案](api/openapi.v1.json)、数据模型、前端字段映射、虚构样例和验收清单。该文档是待三方评审的实现目标，不改变本页列出的实际实现范围。

后续接入建议依次替换：鉴权与岗位 → 草案与规则发布 → 批次与候选人 → 产物和证据 → 电话状态和取消 → 报告审核与服务端导出。所有请求保持在 `src/api/`，使用统一 `/api/v1`；业务数据不能在请求失败时自动降级为演示成功。

接入异步任务后，再增加约 3 秒活动任务轮询、离页和终态取消、服务端错误分类与请求标识、401 会话失效处理。当前没有真实活动任务，因此不虚构任务 ID、执行百分比或轮询端点。
