界面统一采用深墨绿、暖灰白和少量香槟金，组件颜色及弹窗／按钮基础动效集中在 `src/main.tsx` 的 Ant Design token，细节样式在 `src/refinement.css`。`usePageMotion` 对现有主内容做 220ms 轻量入场，快速切换取消上一次动画，不延迟导航、不按路由重挂载岗位生成控制器；工作台只淡入，避免位移破坏触底布局。按钮点击、导航悬浮、岗位／指标卡、标签页、弹窗采用短过渡；尊重系统“减少动态效果”，保留焦点、禁用、加载及真实业务状态。返回列表条件与滚动恢复继续由原导航逻辑维护。

工作台移除“候选人进展”模块，保留指标卡与待办。待办卡片按可视区剩余高度伸缩，桌面底边贴合视口底部，手机底边贴合底部导航上沿；窗口调整后自动适配。标题固定，列表内部滚动并支持键盘聚焦，数量变化不撑高整张卡片。

岗位候选人列表的“状态”仅显示“简历分析／电话沟通／推荐报告待审核”。明确初筛不通过、当前有效报告版本审核确认后移出岗位队列，人才库和历史记录保留；未知仍为简历分析。电话结束但 D10 尚未实际生成成功时仍显示电话沟通。预览可通过现有审核交互验证退出和人数更新，仍仅页面内存；账号区读取接口中的独立状态与具体 D10 引用核验，不能用前端计时推进。电话／报告生成／真实审批仍待后端 B 接入。详见 [状态与退出口径](talent-routing.md#岗位候选人状态与退出)。

界面按用户要求将导航及列表页标题改为“人才库”，移除演示横幅、导入说明、模拟来源标签与相关预览文案。预览数据的说明仅在呈现时省略，原始来源、导出标记、账号隔离与执行校验保持原有语义；不能据此认定真实业务已经接入。

人才列表（账号区与预览区）只保留“候选人／适配岗位／查看信息”。“适配岗位”支持多个初步关联岗位，账号区直接消费人才接口的 `applications`，不按最终初筛结论过滤；预览区使用单独的匹配 ID 列表，搜索和岗位筛选覆盖全部匹配项。列表移除初筛结论、规则版本与初筛筛选器；详情与下游执行校验保留。来源与匹配边界见 [人才入库与职能分流](talent-routing.md)。

“电话沟通情况”和“评估与推荐”均加入“筛选岗位”。预览区按候选人和岗位选择独立流程记录，沟通、D09/D10、报告版本、审核、修订、下载次数及停止状态互不串用；只有初步匹配而没有流程记录的岗位显示空状态。详情地址的第四段保存岗位 ID，刷新保留选择；从岗位候选人列表、电话任务和推荐审核进入时携带当前岗位，筛选切换仍保留原返回入口。切换岗位会卸载原岗位内容与审核表单，防止提交旧岗位操作。下载文件名包含岗位名称，导出再次校验报告所属岗位。预览候选人流程数据仍为内存，刷新不承诺保留人工审核或临时样例内容。

账号区人才列表同样提供三个查看按钮，沿用现有人才详情抽屉；电话和评估视图从该人才的服务端 `applications` 构建岗位选项，切换时查询所选 `application_id`。读取前核对岗位关联，返回内容核对 application/job、产物 ID、版本和类型；不显示其他岗位或不匹配的内容。电话页读取 D07/D08，评估页读取 D09/D10，离开或切换后取消原查询。仍未接入实时电话控制、报告审核及下载服务，不以预览审批代替服务端操作。

多岗位筛选验证（2026-11-15）：静态检查、类型检查、构建及 44 项领域测试通过。隔离浏览器夹具验证了同人多岗位通话／评估／推荐切换、无记录空状态、同版本独立审批、实际 Markdown 下载的岗位与内容、390px 无横向溢出；账号视图用隔离响应验证按 application 查询及跨岗位内容阻断。未执行真实外呼、真实模型或服务端报告审核。

官网、独立登录／注册、全局会话恢复和退出已加入，详见 [官网与账号交付](website-auth.md)。默认进入官网；演示无需登录。账号区岗位从空列表开始，本机数据按账号隔离。

前端为 React / TypeScript / Ant Design。岗位创建和产物页面已加入真实文字分析接口；候选人、电话、推荐仍为明确标记的虚构演示。基础连接、接口类型和构建通过不代表真实业务闭环完成。

新增岗位流程、资料格式、接口顺序、验证证据及后端待接入项见 [从沟通材料创建岗位](job-material-workflow.md)。后端 A 已有实现范围见 [A 交付说明](backend-a-delivery.md)，字段以 [实际 OpenAPI](api/openapi.implemented.v1.json) 和从其生成的 `src/api/generated.ts` 为准。

检查使用 `npm run check` 和 `npm test`。`docx`、`jspdf` 只在导出时加载。未部署或推送。

## 业务边界

候选人使用 `#candidate/{id}/summary`、`/call`、`/reports` 三个独立详情地址，旧的 `#candidate/{id}` 仍打开梗概。详情不再混排三个栏目、流程时间线或全流程产物入口；电话页直接显示 D08 沟通记录，评估推荐页直接显示 D09 与 D10，证据在当前页展开。

页面返回按钮按实际入口返回：候选人列表、电话任务、工作台、推荐审核或岗位。岗位内进入详情后仍返回原来的候选人标签。搜索、岗位筛选、状态、分页和滚动位置在当前标签页保留，兼容浏览器后退与前进；直接打开详情时默认返回候选人列表。筛选和位置使用 sessionStorage，不代表候选人业务数据已持久化。

- 不能把样例或固定响应当作真实模型、联网研究或电话结果。失败不自动降级为模拟成功；未知与冲突保留。
- D01 修改后撤销其确认、D02 标记待复核；D02 修改后仅撤销其自身确认；已绑定历史规则的候选人保持原版本。人工面试维度权重须合计 100%，候选人的实际得分留空。
- 预置达标样例关联唯一模拟电话任务，没有逐人拨号按钮。停止请求等待确认；结果不明不允许直接重拨。
- D09 内部评估与 D10 对外推荐分开。D10 仅导出当前已批准有效版本；修订保留模拟来源并失效旧批准。
