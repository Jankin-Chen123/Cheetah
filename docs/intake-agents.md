# 初筛 Agent：按业务资料实现的 V2

本轮依据 `docs/简历初筛Agent开发资料/` 中五份提示词和五份 Word 表单实现。原始资料未改写；资料中的范例只作格式参考，不作为客户或候选人事实。功能通过隔离响应和本地数据库验证，不代表真实模型、搜索供应商或专业筛选质量已经验收。

## 职责与实际执行

| Agent | 实现 | 输入与输出 |
| --- | --- | --- |
| A01 V1.5 | 一次受控模型提取，程序核查原文并渲染 | 客户材料 → D01：38 个字段及三段 JD，连续两列表格 |
| A02 V1.0 | 独立模型步骤，岗位维度动态生成，建议权重和来源校验 | D01 与原始客户材料 → D02：六列面试标准，五档锚点，不提前填写候选人得分 |
| A04 V1.1 | 一次受控模型提取，程序校验九个完整模块并派生研究清单 | 原始简历 → D03；工作、教育、项目、赛事、论文和其他成果按实际数量重复 |
| A03 V1.0 | 已有 Pi 核心、pi-web-access MCP 插件及四项研究 skills | D03 清单 → 设目标、消歧、搜索、读原文、记录证据、自主停止 → 五部分 D04 |
| A05 V2.1 | 岗位规则建议与逐人评估为不同持久化步骤；程序计算与分流守卫 | D01/D02 → 岗位级七维规则建议；发布后结合 D03/D04 → D05、D06 |

没有为固定提取阶段添加自主工具循环。A03 有逐对象和全任务预算、无进展限制、资源指纹、外部结果回执及恢复边界。所有职责仍在同一后端工程中，不拆成五个服务。

## 岗位任务与规则发布

`POST /api/v1/jobs/{id}/analyze` 启动 A01，随后自动排队 `interview_standard` 和 `screening_standard`。各步骤有自己的任务、预算和外部响应记录；主任务在后续步骤完成前保持 `waiting_conditions`，完成后返回 D01/D02 引用。`continuation_task_id` 可用于定位后续步骤及其错误；岗位的 `active_task_ids` 也包含活动步骤。

模型结果是草案。每个后续步骤绑定 `draft_revision`，猎头修改草案后，旧步骤不能覆盖修改。完成建议流程仍不等于规则已发布。猎头需要查看两个阶段的标准、完善下游推荐配置，再通过已有发布接口确认；D02 的确认版本与 RulePack 一起保存。

新规则使用 `method_config_ref={"config_id":"a05-evidence","version":1}`，并包含 `screening_rubric`。默认研究建议是 `pi-research` v1，但外部研究仍由服务器配置控制，默认禁用。旧的已发布 `predicates` 规则继续按旧逻辑运行；不会偷偷切换评分方法。

初筛七维默认权重为 25/20/15/15/10/10/5。必须在岗位建档时解释权重调整或维度不适用，所有启用权重合计 100%；不能按候选人重新分配。A02 面试权重使用既有合同的 0—1 表示，A05 初筛权重使用百分数。两者各自维护。

## 证据、计分与三分流

- D03 的所有事实保留引用及原始文件关联；没有依据的提取值降为未知。可重复记录保留原始数字、日期精度与角色，不能将团队结果改成个人贡献。
- A05 只能引用本次有效 D03/D04 的证据 ID 和版本，不得升级 E2/E3/U 为 E1。分数需要 E1/E2 支持，个人职责等维度不能只凭公共公司背景评分。跨维度复用证据必须说明不同用途。
- 单维贡献为 `score / 10 × weight`。分别记录已评分贡献 P、已评权重覆盖 C；仅 C=100 时正式总分才非空。未知不会自动记零，也不会转移权重。
- 模型提出三分流建议，程序校验。核心分项没有证据、核心冲突或明显低匹配时不能自动通过；没有多项明确核心差距或已确认的必要资格失败时，不能仅因缺资料拒绝。必要资格否决还必须对应已发布的专业资格条目。
- 薪资仅在币种、税前税后、固定/总包、月/年周期均明确且可比时，由程序比较；含糊薪资保持未评估。第一版支持明确文字金额，复杂奖金、股权和薪数口径不猜测。预算内取 9 分；超过上限 `(0,5%]` 取 8、`(5%,15%]` 取 7、`(15%,30%]` 取 6、`(30%,50%]` 取 4、超过 50% 取 2。该细化填补原材料 0—5% 的空档，属于显式工程约定，需业务验收。
- A05 交给 A06 的是待核实事实、线索与优先级，不是整段面试脚本。通过只登记持久化交接事件，不代表已经打电话或获得联系授权。

模型对引文含义、评分合理性和个人成果归因的语义理解仍需真实案例评测；引用存在、Schema 合法和程序计算正确不能证明业务结论一定正确。

## 模板差异的处理

1. A01 Word 缺少“用人部门”，按 V1.5 提示词补齐五项客户信息，共 38 字段；仍只显示两列。
2. A04 提示词提及分模块表格，Word 使用连续字段表；展示按 Word 连续表组织，九个模块及全部字段保持不变。
3. A05 Word 六列评分表合并 D01/D03/D04 证据，提示词示例八列拆开；内部保存独立证据，展示采用 Word 六列，并将电话交接优先级明确展示。
4. A03 的“第一版不自动开启第二轮”解释为不擅自新增任务或扩大范围。显式启用 Pi 并配置预算后，允许同一任务内定向追查与消歧；A05 不自动触发 A03 返工。达到预算或停止条件必须结束，并保留未知。

## 文件读取、报告与更正

支持 UTF-8 TXT、文本 PDF、DOCX（包括表格文字），以及 Word 97—2003 DOC 主文档文本。DOC 使用受限的 OLE/文本片段表读取，不启动 Office，不执行宏或外部链接；加密、损坏或无法可靠读取时逐份拒绝。PDF 页数、文件大小、解压大小和文本长度受限；图片 OCR 与加密 PDF 未接入。完全无法识别时明确失败；部分空白/扫描页面和嵌入内容保留未识别标记，使 D03 为部分完成，网页显示限制和补充材料提示。

D01/D02/D03 按标准表单渲染 Markdown；D04 沿用五部分报告；同一候选人的 D05/D06 合并显示，并绑定具体输入版本。此版未新增 Word 文件下载，结构化数据和 Markdown 可供后续文件生成模块使用。

更正支持既有 `/facts/...`、`/research_objects/...`，以及 `/resume_form/{模块名}/{record_id}/{字段名}` 路径。更正会保存完整 D03 新版本，保留元信息并同步研究清单；下游旧产物及未消费交接失效，需要显式重算，不默认重拨或交付。

## 资源、配置与验证

原始提示词副本和宿主适配说明位于 `backend/agents/intake/resources/`，manifest 保存源文件名和 SHA-256。新任务绑定提示词/合同指纹，指纹改变时拒绝使用新版本继续旧任务。A03 也从同一组已校验源提示词读取其业务约定。

沿用现有可配置 HTTPS Chat Completions 模型封装，无固定供应商或密钥。`CHEETA_MODEL_MAX_OUTPUT_TOKENS` 默认提升为 16000，可按供应商能力配置；完整长简历可能需要更大输出额度。预算仍由服务器强制执行。接口不支持、模型返回不完整 JSON 或缺少必要模块时任务明确失败，不自动用模拟结果替代。

2026-11-15 内测兼容修复：DeepSeek 模型的结构化提取默认发送 `thinking.type=disabled`，防止推理占满输出额度；其他模型默认不发送该扩展。`CHEETA_MODEL_THINKING` 可显式设为 enabled/disabled。模型读取超时默认 90 秒，步骤租期默认 300 秒。JSON 对象可带完整 Markdown 代码围栏；仅在正常结束时允许恢复括号/分隔符，且逐一核对键、标量和冒号序列不变，再执行完整结构与原文校验。截断、缺失字符串/值或需要改变事实的响应仍失败。

模型把未知项带回确定值时，程序清空值并保留未知；兼容摘要中误加的 note 不进入事实模型，完整表单的说明保留。已有章节放错容器时只恢复既有章节，缺失章节不补造。已确认的坏响应结算用量并保存在受保护的任务缓存，不能误标为外部结果未知；格式修复后的显式重试只重放缓存，次数仍受限，不再次请求模型。截断返回 `MODEL_OUTPUT_TRUNCATED`，其他不可可靠恢复的格式返回 `MODEL_OUTPUT_INVALID`。真正外部结果不明仍保持 reconciling，不自动重发。

合同由 `backend/scripts/export_intake_schema.py` 生成。校验命令：

```powershell
cd backend
uv run ruff check .
uv run ruff format --check .
uv run pytest
uv run python scripts/export_intake_schema.py --check
uv run python scripts/export_a03_schema.py --check
uv run python scripts/export_http_schema.py --check
```

`tests/test_agent_forms.py` 覆盖完整表单、重复对象、引文降级、固定权重、缺项覆盖率、薪资边界、证据伪造、DOCX、完整链路、规则草案冲突、更正失效、人工复核与资源指纹。`test_http_pipeline.py` 使用隔离 HTTP 响应验证模型/搜索协议。既有 Pi 测试验证真实 Pi 核心与已安装 MCP 插件的执行合同，但业务响应依然是隔离 fixture。

真实模型完整业务联调、脱敏业务标注集、真实电话、完整应用容器和线上部署仍待验收。模型端点已单独以虚构短文本验证 JSON 输出与工具调用；DeepSeek 搜索及正文读取已复用用户提供的 API 账户完成单接口实测，详见 [A03 Pi Agent](a03-pi-agent.md)。其他搜索提供者尚未验收。PostgreSQL 数据库容器已单独验证，见 [容器数据库说明](container-database.md)。前端页面实际接入范围以单独的前端交付记录为准，本轮不将后端测试当作页面验收。
