# 从沟通材料创建岗位

用户最新要求：上传招聘沟通录音，或粘贴／导入录音文字，识别后生成 D01 岗位画像和 D02 岗位面试评估表。两份产物在网页留存，可查看、修改和导出 PDF / Word。此要求优先于旧计划中延后录音与文件导出的安排。

## 当前实现

- 创建窗口默认显示录音上传，不再用选项卡区分录音／文字；“没有录音？使用文字记录”是可选展开项，支持单独提交文字或为录音补充文字。文字支持粘贴与 UTF-8 TXT，最多 30,000 字；不要求先填岗位、企业、地点和薪资。
- 录音最多 100 MB，保存在本机，可播放。**自动转写尚未实现**；补充文字记录后才能调用文字分析。录音不会被冒充为已转写，也不会自动上传到模型服务。
- “原始材料”分别展示原始录音、原始文字、识别用文字（修正后与原文不同时）和沟通纪要。录音可播放、下载；上传 TXT 保留文件名、类型、大小和原始 Blob，下载保持原字节；粘贴文字可下载为 TXT。上传后修改识别用文字，不覆盖上传原件与原文。
- 沟通纪要复用已返回的 D01 模型提取要点（已陈述字段、冲突和待核实事项），单独保留快照并支持 TXT 下载，不重复调用模型。纪要绑定产物 ID／版本、输入文字、生成时间与真实／模拟／人工来源；编辑岗位画像不改写纪要。同一产物版本不重复留存；已有远程画像但缺纪要的岗位，重新打开时从原产物恢复。它是现有提取结果的文字投影，**不是额外模型摘要步骤，也不是录音转写原文**。
- D01 使用 A01 的 38 字段和 JD 三段，两列连续表格；未提及与待确认分别保留。
- D02 使用 A02 的客户信息、动态能力维度、六列表格、五档评分标准和汇总；实际得分、折算得分留空。人工修改要求维度权重合计 100%。
- 岗位页只显示当前产物，不提供历史版本切换、替换或回退；“岗位与规则”及单独规则草案编辑模块已移除，旧 overview 路径回落到岗位产物。
- 提交材料后返回招聘岗位列表，新卡片置于首位并清空该列表的搜索与状态筛选。账号区文字分析的卡片在等待、排队及执行期间显示灰色“生成中”，整张卡片不可点击且无悬浮抬起效果；只收到 D01 仍继续等待 D02。生成任务在当前工作空间内持续运行，切换页面不重复启动；刷新按保存的岗位、任务 ID 和幂等 key 恢复。仅录音显示“待补充文字”，演示区未启动任务显示“待生成”，失败显示“生成失败”并允许进入查看原因，不冒充持续处理中。
- 卡片不提供单独的“管理岗位”按钮，正常状态整张卡片可点击进入岗位详情，支持键盘聚焦及回车。鼠标悬浮时上移 4px 并增加柔和阴影；减少动态效果偏好下不位移。生成中的卡片不渲染详情链接。
- D01／D02 各有确认按钮，先确认画像再确认面试表。生成完成后卡片恢复操作并显示“待确认”；两份均确认后隐藏卡片右上角标签。修改后需复核时显示“待复核”，筛选项与卡片共用状态，标签不包含“产物”。详情页仅在岗位名旁显示未确认提醒，两份均确认后隐藏；移除独立状态／岗位标识栏。确认时间保存在本机，刷新保留；缺失岗位名称／企业、维度不完整、权重不合计 100%、预填实际分或客户岗位信息冲突均阻止确认。
- 修改只操作当前内容，保存时填写原因，内部保留不可变修订及来源审计，但不提供历史切换。修改 D01 撤销其确认并使 D02 待复核；修改 D02 仅撤销其自身确认。已绑定历史规则的候选人保持原版本。
- 两份产物分别通过各自的导出按钮导出，移除顶部“网页留存”说明及“导出两份产物”整行工具栏。Word 为可编辑表格，PDF 为 A4 打印图像版（中文可见，不是可检索文本）；D01 纵向、D02 横向。导出保留来源、版本和实际确认状态。

## 实际接口调用

前端入口：`src/components/CreateJob.tsx`；`JobWorkspace.tsx` 为每个岗位持续挂载唯一生成控制器，`JobDocuments.tsx` 复用其重试与登录操作。请求统一在 `src/api/jobIntake.ts`，默认 `/api/v1`。

1. 在账号工作区 GET `/auth/me` 恢复会话；401 时由全局入口重新登录，POST `/auth/login`，取得 Cookie 和 CSRF。也可先通过 `/auth/register` 注册独立账号。账号密码不写入本地岗位库；演示区不提交后端分析。
2. 检查 `capabilities.model_configured`；配置存在不代表供应商可用。POST `/jobs` 只发送 `{ "material_text": "…" }`，使用持久化的幂等 key。
3. `CreateJobInput.title/company` 可省略或为 null；提供时仍须非空且不超过 100 字。返回的“待识别岗位／企业”仅为展示标签，不能写入源事实。A01 表单与引文校验通过后，才从 stated 字段回填未由用户指定的标签。
4. POST `/jobs/{id}/analyze`，携带 CSRF、幂等 key、`expected_revision` 和 `execution_mode: live`。
5. 每约 3 秒读取 job、task 和 continuation task，再按 `d01_ref/d02_ref` 获取具体版本产物。**主任务完成不等于两份产物齐全**；已有 D01 时仍等待 D02。两份均到达后停止该岗位轮询，后端后续 A05 标准任务仍可能运行。
6. 工作空间内切换页面保持生成控制器；退出当前工作空间时取消请求，刷新或重新进入后按保存的岗位／任务 ID 恢复。网络结果不明沿用原 key，不自动创建另一岗位；已经尝试提交的材料不再原地改写。任务失败显示原因，“重新检查”只查询／恢复原意图，不替代后端任务重试。

返回产物须为请求的 ID、版本、D01/D02 类型、valid 状态及可识别来源。HTTP live 映射前端 real，mock 来源和人工继承来源贯穿版本与导出。请求失败不会以演示内容替代成功。

## 持久化边界

岗位原文、录音和 TXT 原文件 Blob、识别用文字、沟通纪要快照、产物快照、人工版本、任务与幂等 key 使用 IndexedDB。状态栏显示保存中或失败；刷新可恢复。候选人、电话和推荐演示仍为页面内存。旧记录若当时未保留 TXT 原件，无法补回原文件字节，只能保留已存文字。

真实生成的服务端产物由后端保存；**人工修订版本目前只在当前浏览器、当前来源地址保存，不会回写后端**。`localhost` 与 `127.0.0.1` 是不同存储来源，不支持跨设备同步、多人编辑或跨标签并发合并；清理站点存储会丢失本机版本。清空前可导出备份。

本机确认和修订不会自动发布规则、重算候选人、拨号或交付报告。正式下游使用之前，必须对接服务端的事实更正／草案／发布与版本失效流程；不能把本机表格当作已发布规则包。前端内部 JobDocument.status 的 confirmed 与 HTTP 产物 status、RulePack 发布状态相互独立，不得直接上传为后端状态。
