# 从沟通材料创建岗位

用户最新要求：上传招聘沟通录音，或粘贴／导入录音文字，识别后生成 D01 岗位画像和 D02 岗位面试评估表。两份产物在网页留存，可查看、修改和导出 PDF / Word。此要求优先于旧计划中延后录音与文件导出的安排。

## 当前实现

- 创建窗口不要求先填岗位、企业、地点和薪资；文字支持粘贴与 UTF-8 TXT，最多 30,000 字。
- 录音最多 100 MB，保存在本机，可播放。**自动转写尚未实现**；补充文字记录后才能调用文字分析。录音不会被冒充为已转写，也不会自动上传到模型服务。
- D01 使用 A01 的 38 字段和 JD 三段，两列连续表格；未提及与待确认分别保留。
- D02 使用 A02 的客户信息、动态能力维度、六列表格、五档评分标准和汇总；实际得分、折算得分留空。人工修改要求维度权重合计 100%。
- 人工保存产生新版本，必须填写原因；历史版本只读。D01 变化使 D02 待复核、测试规则回到草稿；D02 复核保存后才恢复导出。已有候选人的历史规则版本保持不变。
- 两份产物可以分别导出，也可合并导出一个文件。Word 为可编辑表格，PDF 为 A4 打印图像版（中文可见，不是可检索文本）；D01 纵向、D02 横向。导出保留来源、版本和待确认标识。

## 实际接口调用

前端入口：`src/components/CreateJob.tsx`、`JobDocuments.tsx`；请求统一在 `src/api/jobIntake.ts`，默认 `/api/v1`。

1. 在账号工作区 GET `/auth/me` 恢复会话；401 时由全局入口重新登录，POST `/auth/login`，取得 Cookie 和 CSRF。也可先通过 `/auth/register` 注册独立账号。账号密码不写入本地岗位库；演示区不提交后端分析。
2. 检查 `capabilities.model_configured`；配置存在不代表供应商可用。POST `/jobs` 只发送 `{ "material_text": "…" }`，使用持久化的幂等 key。
3. `CreateJobInput.title/company` 可省略或为 null；提供时仍须非空且不超过 100 字。返回的“待识别岗位／企业”仅为展示标签，不能写入源事实。A01 表单与引文校验通过后，才从 stated 字段回填未由用户指定的标签。
4. POST `/jobs/{id}/analyze`，携带 CSRF、幂等 key、`expected_revision` 和 `execution_mode: live`。
5. 每约 3 秒读取 job、task 和 continuation task，再按 `d01_ref/d02_ref` 获取具体版本产物。**主任务完成不等于两份产物齐全**；已有 D01 时仍等待 D02。两份均到达后停止本页轮询，后端后续 A05 标准任务仍可能运行。
6. 刷新、离页后按保存的岗位／任务 ID 恢复。网络结果不明沿用原 key，不自动创建另一岗位；已经尝试提交的材料不再原地改写。任务失败显示原因，“重新检查”只查询／恢复原意图，不替代后端任务重试。

返回产物须为请求的 ID、版本、D01/D02 类型、valid 状态及可识别来源。HTTP live 映射前端 real，mock 来源和人工继承来源贯穿版本与导出。请求失败不会以演示内容替代成功。

## 持久化边界

岗位原文、录音 Blob、产物快照、人工版本、任务与幂等 key 使用 IndexedDB。状态栏显示保存中或失败；刷新可恢复。候选人、电话和推荐演示仍为页面内存。

真实生成的服务端产物由后端保存；**人工修订版本目前只在当前浏览器、当前来源地址保存，不会回写后端**。`localhost` 与 `127.0.0.1` 是不同存储来源，不支持跨设备同步、多人编辑或跨标签并发合并；清理站点存储会丢失本机版本。清空前可导出备份。

本机修订不会自动发布规则、重算候选人、拨号或交付报告。正式下游使用之前，必须对接服务端的事实更正／草案／发布与版本失效流程；不能把本机表格当作已发布规则包。
